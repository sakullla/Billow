# Billow 自研 Rust 内核、双内核切换与 iOS 支持

日期：2026-11-20

## 一屏摘要

Windows、macOS、Linux、Android 和 iOS 用户都可以在 Billow 自研原生 Rust 内核与 Mihomo 之间双向切换，继续使用原有配置。iPhone 上两个内核均可建立 VPN 连接（R1）。
Rust 内核首版即以同一 Billow 版本随附的 Mihomo 为完整兼容基准（R2）。
iOS 真机上，Rust 内核运行时整个 VPN 系统扩展的峰值内存预算为 **40 MB**（R3）。通过反复创建、释放资源来检验内存泄漏，验收依据是峰值和资源回收情况，无固定运行时长要求（R4）。

## 完整需求

### R1 各平台可双向切换实际承载流量的内核

用户选择 Rust 内核后，由 Billow 自研的原生 Rust 内核处理流量；用户也可以切回 Mihomo。两个方向均可复用当前订阅或本地配置。

- 在 Windows、macOS、Linux 和 Android 上，使用一份有效配置，分别完成 Mihomo → Rust 和 Rust → Mihomo 切换。每次切换后，发起新的代理请求，核对实际承载请求的内核及出站结果。
- 在 iPhone 真机上用同一配置完成上述双向切换。分别用两个内核建立系统 VPN，从其他应用发起命中代理规则的请求，验证流量确实经过所选内核并到达预期出口。
- 切换后若所选内核未能建立连接，界面应反映失败；仅改变内核名称或显示已连接，均不足以判定切换成功。

### R2 首版完整兼容随附 Mihomo 的有效配置与代理行为

以同一 Billow 版本随附的 Mihomo 为对照。凡该内核在对应平台能使用的配置，用户切换到 Rust 后应能原样使用，包括订阅、本地 YAML 及 Billow 应用覆写后的有效配置。兼容范围覆盖该版本支持的能力，包括节点协议及其选项、策略组、DNS、分流规则和规则集。

- 固定配置、节点、解析条件和测试流量，先记录 Mihomo 的结果，再用 Rust 核验。比对协议连接结果、策略组选择、DNS 处理、命中规则和实际出口；对于依赖外部响应的行为，保持两次验证的输入一致。
- 对组合使用上述能力的配置，核验一次请求从解析、匹配规则到经选定节点出站的完整结果。Rust 拒绝有效配置、要求用户删改字段、静默忽略配置项或导致流量走错出口，均判定为兼容失败。

### R3 iOS 系统扩展的内存峰值不超过 40 MB

预算适用于 iPhone 上承载 Rust 内核的整个 VPN 系统扩展，包含内核、规则数据、连接缓冲区及扩展自身开销。统一按十进制 MB 记录，40 MB 为 40,000,000 字节。

- 在真机上记录扩展进程的内存占用，覆盖启动与配置加载、锁屏空闲、并发连接与持续转发、规则集更新，以及 Wi-Fi 与蜂窝网络之间的切换和重连。记录设备、系统版本、配置、负载和各场景峰值，以便复测。
- 每个场景的峰值均须在预算内，包括规则集更新和重连过程中的瞬时峰值。扩展须能完成相应操作并继续转发流量；出现内存超限、因内存压力被系统终止，或更新后无法恢复转发，均判定失败。

### R4 重复使用后资源可回收，内存基线可稳定

在同一台 iPhone 上使用固定配置和负载，记录 Rust 内核所在 VPN 扩展预热后的空闲占用。反复建立并关闭连接、重载同一规则集、断网再重连。每轮结束时回到等价空闲状态，比较内存占用，并检查已结束连接、已替换规则集及相关缓冲区的存活情况。

- 有界缓存可以在预热期间增长。负载和缓存内容稳定后，空闲占用应趋于稳定，已失效资源应可回收。
- 已失效对象持续累积，或相同负载下空闲基线持续抬升而不能稳定，均判定失败，即便峰值仍低于 40 MB。验收以可重复的资源生命周期和内存观测为准。
