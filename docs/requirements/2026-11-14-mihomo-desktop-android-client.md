# 需求：Billow

日期：2026-11-14

更新：2026-11-14

## 一屏摘要

- 目标：名为 Billow 的 Mihomo 图形客户端，用自备配置在四个系统上开关代理（R1、R21）
- 使用者：已有 Mihomo/Clash.Meta 订阅或本地配置的人；程序不提供节点或订阅服务（R1）
- 范围：配置、代理组与延迟、桌面系统代理和 TUN、Android VPN 与分应用、覆写、连接和日志、简体中文，以及 Tauri/Rust 客户端（R1–R7、R16）
- 界面：三项导航；连接即打开系统代理或 VPN，TUN 单独说明；首页显示余量、手动节点和诊断入口；覆写收在高级里（R1、R3、R5、R17–R20）
- 关键行为：订阅或内核启用失败时，系统代理、TUN 和 VPN 处于关闭；TUN 或 VPN 权限被拒时显示失败且不显示为已连接；无效覆写不替换生效配置；应用侧集成在 Rust，壳使用系统 WebView（R1、R3、R4、R5、R16）
- 成功标准：可用配置能开启对应代理并看到连接或日志；无效订阅不开启代理；被排除应用不进 VPN；有效覆写改变生效配置；四个平台都能产出 Tauri 应用（R1、R4、R5、R6、R16）
- 不做事项：快捷磁贴、全局热键、Android TV、WebDAV、请求与 DNS 明细、Sub-Store、双内核、连接内容查看（R8–R15）
- 假设：新程序且不改两个参考仓库；多配置同时只生效一份；界面为简体中文；Android 默认全部应用进入 VPN；启动后进入首页；主题默认可跟随系统；桌面记住窗口尺寸和上次入口（R1、R4、R7、R17–R19）

## 完整需求

### R1 配置导入与生效

行为：使用者可以添加 Mihomo/Clash.Meta 订阅链接或本地配置文件。假设可以保存多份配置，同一时间只有一份生效。使用者启用某一份时，该份成为内核使用的配置。配置页列出已保存的全部配置，当前生效的一份有唯一标记。添加时分成订阅链接和本地文件两个入口。系统用一条订阅链接打开应用时，进入同一个确认层，看到链接并确认后才添加，不静默启用。订阅响应带有 `subscription-userinfo` 且总量大于 0 时，首页当前配置和配置页该行显示已用流量和总流量；到期时间只在该信息里的到期值大于 0 时显示。没有该信息时不显示余量，也不编造数字。失败原因写在对应配置上，直到该配置下一次启用成功或使用者再次尝试。

适用与失败边界：适用于 Windows、macOS、Linux 和 Android。本需求交付新客户端，不要求修改 FlClash 或 Sparkle 仓库，也不提供节点或订阅服务。本要求不包含无人值守的定时更新。添加、更新或启用时，若订阅内容没有取回、本地文件无法作为 Mihomo 配置应用，或内核没有启动成功，界面显示错误，该次启用不生效，系统代理、TUN 和 VPN 处于关闭。

验收：

- 给定一份可取回的订阅或一份可用的本地配置并启用后，界面显示该配置为当前唯一生效配置
- 添加两份可用配置并分别启用时，界面标明的生效配置随启用动作改变，且同时只有一份为生效
- 给定一份无法取回的订阅，或一份不能作为 Mihomo 配置应用的本地文件，并启用时，界面显示错误，系统代理、TUN 和 VPN 处于关闭，且该配置上仍能看到这次失败原因
- 两份配置同时存在时，只有当前生效的一份带有当前标记；添加订阅链接和添加本地文件是两个分开的入口
- 订阅响应包含总量大于 0 的 `subscription-userinfo` 时，首页和该配置行能看到已用流量和总流量；到期值大于 0 时能看到到期时间，到期值为 0 时不显示到期；没有该信息时这两处没有余量数字
- 系统用一条订阅链接打开应用时，先看到确认层中的链接，确认后才成为已保存配置；取消后不新增配置

### R2 代理组与延迟

行为：已保存到本地的配置可以在节点页按组列出节点，内核当时是否在运行都可以。可手动选择的组能切换节点，选择记在该配置上。内核正在运行时选择立即生效；未运行时界面仍把该节点标为当前选择，并在下次连接成功后生效。自动选择的组只展示当前节点，不能手动改选。使用者能按名称筛选节点，并能对一组主动发起延迟测试。测试完成后，该组可按延迟或名称排列。仅打开节点页时，不自动测试全部节点。

适用与失败边界：配置还没有成功保存到本地时，节点页说明需要先添加或更新配置，切换不显示为成功。不允许手动选择的组不能切换成功。某一个节点测试失败时，只将该节点标为失败，已成功的其它节点结果保留。

验收：

- 内核运行时打开代理组，能看到组内节点
- 在允许手动选择的组中选定一个节点后，当前选择变为该节点
- 对多个节点测试延迟时，成功的节点显示延迟，失败的节点显示失败，其它已成功结果仍在
- 配置已在本地且内核未运行时，选定手动组的一个节点后，界面把该节点标为当前选择；之后连接成功，该组使用这个节点
- 配置还没有本地内容时，节点页不显示切换成功，并说明需要先添加或更新配置；不允许手动选择的组不能改选
- 输入节点名称的一部分后，列表只保留名称匹配的节点
- 主动测试一组后按延迟排列，失败节点仍显示为失败；只打开节点页、不开始测试时，该组不出现新的延迟结果

### R3 桌面系统代理与 TUN

行为：在 Windows、macOS 和 Linux 上，使用者可以在首页分别开启或关闭系统代理和 TUN。系统代理的说明是「浏览器和遵守系统设置的应用」。TUN 的说明是「不遵守系统代理的应用也走代理，并需要系统授权」。系统代理开启后，遵守系统代理的程序走该代理。TUN 开启后，本机流量走 TUN。连接不会自动打开 TUN。使用者改变过 TUN 之后，记住开或关，下次连接沿用该选择。这两项不单独占用导航入口。

适用与失败边界：不适用于 Android。桌面 TUN 所需权限被拒绝时，界面显示失败，TUN 为关闭，且不显示为已连接。内核没有启动成功时，系统代理和 TUN 处于关闭。使用者关闭二者后，系统代理不再指向本程序，TUN 为关闭。

验收：

- 在桌面开启系统代理后，系统的代理设置指向本程序提供的代理；关闭后，系统代理不再指向它
- 在桌面授予权限并开启 TUN 后，界面显示 TUN 已开启；第一次点连接时 TUN 保持关闭
- 使用者打开 TUN 并断开后再次连接，TUN 仍为开启；使用者关闭 TUN 后再次连接，TUN 仍为关闭
- 拒绝 TUN 权限时，界面显示失败，TUN 为关闭，且不显示为已连接；这次拒绝不改变系统代理原先的开闭状态
- 内核没有启动成功时，界面显示失败，系统代理和 TUN 均为关闭

### R4 Android VPN 与分应用

行为：在 Android 上，使用者在首页通过 VPN 启用代理。假设已安装应用默认都进入 VPN，使用者可以把指定应用排除。按应用排除从首页进入，可按应用名称搜索，已排除和未排除能够区分。被排除应用的流量不进入 VPN，未排除应用的流量进入 VPN。

适用与失败边界：仅适用于 Android。VPN 权限被拒绝时，界面显示失败，VPN 为关闭，且不显示为已连接。配置启用失败或内核没有启动成功时，VPN 处于关闭。桌面系统不使用这套按应用排除。

验收：

- 授予 VPN 权限并成功启用后，界面显示 VPN 已开启
- 拒绝 VPN 权限，或内核没有启动成功时，界面显示失败，VPN 为关闭
- 排除一个应用后，该应用产生的访问不进入 VPN；未排除的应用产生的访问仍进入 VPN
- 在 Android 首页可以开关 VPN，并进入按应用排除；搜索一个应用名后只保留名称匹配的应用，排除后该项显示为已排除

### R5 配置覆写

行为：每份配置各自有一段覆写，从该配置的「高级」进入编辑和保存，不与启用、更新并列。再次应用这份配置时，内核使用这段覆写作用之后的结果。切换到另一份配置时，使用那一份自己的覆写。

适用与失败边界：覆写在切换生效配置之前就被判定无法应用时，界面显示错误，生效配置保持上一次成功应用的结果，已开启的代理保持开启，处于关闭的系统代理、TUN 或 VPN 不被这次失败打开。若应用后的配置导致内核没有启动成功，结果与 R1 的启用失败相同。没有覆写时，生效内容与原配置一致。

验收：

- 保存一条改变某个可见配置值的有效覆写并应用后，界面上的当前生效值变为该新值
- 代理处于关闭时，保存一条在切换前就无法应用的覆写并应用，界面显示错误，生效配置不变，系统代理、TUN 和 VPN 仍为关闭
- 代理已开启且已有上一次成功配置时，应用一条在切换前就无法应用的覆写，界面显示错误，生效配置不变，代理保持开启
- 两份配置各保存一段不同覆写后分别启用，当前生效值随所启用的那一份变化；无法应用的覆写在编辑处显示错误，不进入生效配置
- 配置主行能看到启用或更新，要展开「高级」才能进入覆写

### R6 当前连接与运行日志

行为：内核运行时，使用者能看到当前连接和运行日志。连接和日志不在主导航中，也不放在配置页，而是首页底部的「连接与日志」和失败原因上的「查看诊断」打开同一诊断页，页内用分段切换。每条当前连接至少显示目标主机和所使用的出站或代理名称，并可按目标文字筛选。日志默认停在最新一条；使用者向上滚动查看旧记录时，新日志不再把位置拉回底部。日志可按级别筛选，以便留下失败记录。

适用与失败边界：内核未运行时，界面不显示为已连接，当前连接列表不再把已停止的会话显示为仍在连接。启动失败时，运行日志或同等可见位置能看到这次失败。连接列表只要求能够识别当前连接。

验收：

- 内核运行并产生流量时，当前连接列表出现对应连接
- 内核停止后，界面不显示为已连接，已停止的会话不再显示为仍在连接
- 一次启动失败后，使用者能在运行日志或同等位置看到这次失败记录
- 当前连接可以按目标文字筛到对应的一条，并且该条能看出目标主机和出站或代理名称
- 日志停在底部时，新记录出现后仍能看到最新一条；向上滚动后，新记录不把滚动位置拉回底部
- 从首页底部的「连接与日志」和失败原因上的「查看诊断」都能打开诊断页，并在连接和日志两个分段之间切换；配置页没有这个入口

### R7 简体中文界面

行为：主路径上的操作名称、状态和错误说明以简体中文显示。假设第一版界面语言为简体中文。

适用与失败边界：适用于 R1–R6 与 R17–R20 的界面文字。不要求同时提供其它语言。错误说明仍要能区分成功与失败。

验收：

- 首页、节点、配置、连接与日志、出站模式、主题、系统代理、TUN、VPN、覆写和失败说明使用简体中文

### R16 Tauri 与 Rust 客户端

行为：Windows、macOS、Linux 和 Android 上的客户端都是 Tauri 应用。配置、代理组操作、系统代理、TUN、Android VPN 与分应用、覆写、连接和日志的应用侧逻辑由 Rust 实现。客户端使用操作系统自带的 WebView。

适用与失败边界：四个平台都适用。代理数据面仍使用 R14 的单一 Mihomo 内核，不要求用 Rust 重写该内核。用户没有给出启动时间、内存或安装体积数字，因此不设这类阈值；轻量以使用系统 WebView、不自带独立浏览器运行时为准。某个平台构建不出可安装的 Tauri 产物，或上述应用侧逻辑不在 Rust 中，则本要求失败。Android 的 VPN 与分应用结果仍按 R4 验收。

验收：

- 四个平台各自能构建出 Tauri 应用的安装产物，并在对应系统上完成 R1 的启用配置
- 系统代理、TUN、Android VPN、配置启用和覆写的应用侧实现位于 Rust
- 安装产物使用系统 WebView，不包含一套独立的浏览器运行时

### R17 导航与布局

行为：手机、窄桌面和宽桌面使用同一套三个主入口，顺序为首页、节点、配置，并且都显示文字。宽桌面用侧栏，窄桌面和 Android 用底部导航。连接、日志、主题、覆写、系统代理、TUN、VPN 和按应用排除都不占主入口。主题放在配置页里。假设桌面再次打开时恢复上次窗口尺寸和上次所在的主入口。

适用与失败边界：四个平台都适用。主导航只有这三项。导航中不出现请求明细、DNS 查询、Sub-Store 或内核版本切换。Android 不把系统代理和 TUN 当作入口；桌面不把按应用排除当作入口。上次入口如果不是这三项，则回到首页。窗口尺寸恢复失败时仍能打开到可用窗口，不阻止进入首页。

验收：

- 四个平台的主导航都只有首页、节点、配置，且当前项有标记
- 把桌面窗口缩到侧栏与内容列无法并列时，导航变为底部这三项；加宽到可以并列时恢复侧栏
- 主导航中没有连接、日志、主题、请求明细、DNS 查询、Sub-Store 或内核版本切换
- 桌面停在节点页并改变窗口尺寸后重新打开，仍在节点页，且窗口尺寸与上次一致

### R18 首页状态与主操作

行为：假设启动后第一屏是首页。首页显示内核状态：未连接、连接中、已连接，以及当前生效配置的名称和出站模式：规则、全局、直连。规则的说明是按配置自动选择，全局的说明是全部走当前节点，直连的说明是新连接不走代理。桌面点连接会启动内核并打开系统代理，不因此打开 TUN；Android 点连接会启动内核并请求 VPN。只有对应的接管已经打开才显示已连接。桌面在首页切换系统代理和 TUN，Android 在首页切换 VPN。已连接时用文字显示当前上行和下行速率，不使用速率曲线。主操作在未连接时为连接，已连接时为断开。首页列出可手动选择的组及其当前节点，自动选择的组不在首页挑选。首页底部有文字入口「连接与日志」。最近一次连接或模式切换失败的原因保留在首页上，并带有查看诊断，直到下一次连接成功或使用者再次发起连接。

适用与失败边界：没有配置时状态为未连接，主操作是添加配置，并直接打开添加层，不先跳去别的页面。连接中时再次使用主操作不会启动第二套内核。系统代理或 VPN 没有打开时不显示已连接。模式切换失败时保持切换前的模式并显示错误。断开后系统代理、TUN 和 VPN 处于关闭，速率文字消失。直连只改变新连接的出站，不单独改写系统代理开关。首页不提供可拖拽或可增删的卡片编辑。

验收：

- 没有配置时，第一屏是首页，状态为未连接；点添加配置后直接出现添加层
- 桌面有可用配置时第一次点连接，状态经过连接中后变为已连接，系统代理指向本程序，TUN 仍为关闭，并显示当前配置名和上行、下行文字；点断开后变为未连接，系统代理、TUN 和 VPN 处于关闭
- Android 授予 VPN 后点连接，状态变为已连接；拒绝 VPN 权限时不显示已连接
- 首页能看到每个可手动选择的组的当前节点，看不到需要手动挑选的自动组；当前模式下方能看到对应的一句说明
- 已连接时把模式从规则改为直连，首页显示直连；改回规则后显示规则。切换失败时模式不变，且首页能看到失败原因
- 启用一份无法取回的订阅后，失败原因留在首页上，并可以从这里打开诊断，不需要先在导航里找日志
- 状态为连接中时再次点主操作，不会出现第二套已连接内核，状态仍是这一次连接的结果

### R19 视觉与边界反馈

行为：界面保持现代、简单、完成度高。主题可以跟随系统、始终浅色或始终深色，假设默认跟随系统。浅色和深色各自有页面底色和内容底色，两者能分开。首页上的连接状态是该屏最大的文字。每一屏最多一个实心主按钮。主按钮、模式分段和选中行使用同一套圆角，强调色只有一种，并只用于当前导航、主按钮、开启的开关和选中行。连接状态、延迟结果和失败除颜色外还有文字。同一列表在 Android 上的行高大于桌面，点按节点整行即可选择允许手动选择的节点。状态切换不被开场动画挡住。系统开启减少动态效果时，不播放持续的装饰动画。

适用与失败边界：四个平台都适用。块之间用留白和细分隔区分，不用多层阴影、渐变背景、毛玻璃叠层或插画空状态。速率和延迟使用等宽数字。界面使用系统界面字体。桌面键盘焦点停在导航、开关和节点行时有可见焦点。不提供动态取色或可更换的装饰主题。减少动态效果只约束装饰动画，不取消状态文字和操作结果。

验收：

- 系统为深色且主题为跟随时，界面为深色；改为始终浅色后保持浅色。两种主题都能看出页面底和内容块不是同一种底色
- 首页上「未连接」「连接中」或「已连接」的字号大于配置名、按钮和列表文字；该屏同时只有一个实心按钮
- 主按钮、模式分段和选中行的圆角一致，页面上看不到第二种强调色、毛玻璃叠层或彩色渐变背景
- 延迟失败的节点不依赖颜色，文字本身标明失败；延迟数字位数变化时，数字列不左右跳动
- 系统开启减少动态效果时，首页和节点页没有持续循环的装饰动画，空状态也没有插画
- 同一代理组在 Android 上的单行高度大于桌面；点按允许手动选择的节点整行后，当前选择变为该节点
- 在桌面用键盘把焦点移到侧栏和节点行时，能看出当前焦点

### R20 各屏结构

行为：首页自上而下是状态词与当前配置名、有余量时的流量、失败原因、主按钮、规则/全局/直连分段及其一句说明、平台开关、可手动选择的组及其当前节点、已连接时的上传和下载、底部文字「连接与日志」。宽桌面把状态到开关放在左列，当前节点和速率放在右列。点某个手动组进入节点页并定位到该组。节点页顶部是搜索；每一组有组名、手动或自动、当前节点、测试和排序，排序为默认、延迟、名称；节点一行，名称在左、延迟在右，选中行有勾选。配置页把当前生效配置固定在列表顶部，行内有名称、订阅或本地、最近成功时间或失败原因，以及有余量时的流量；非当前项可启用，当前订阅可更新。覆写放在该配置的「高级」里。配置页在列表之后只提供主题。添加配置另开一层，里面是订阅链接和本地文件两个动作。覆写再开一层，含编辑区、保存和紧挨编辑区的错误，输入过程中不应用到内核。诊断页内用分段切换连接和日志。连接分段顶部可搜索，每行以目标主机为主、出站名称为辅。日志分段可在全部、错误、警告、信息之间筛选，日志正文用等宽字，周围控件不用等宽字。Android 按应用排除从首页的 VPN 区域进入，顶部可搜索，每行是应用名和排除开关，返回后回到首页。

适用与失败边界：没有配置时，首页只留状态和添加配置。搜索无匹配时，节点页和按应用排除各自显示没有匹配项，不清空已保存数据。自动组的节点可见但整行不能选中。未连接时连接分段不保留上一次的连接行，并显示未连接；已连接但没有连接时显示没有当前连接。覆写层关闭且未保存时，编辑内容不进入内核。

验收：

- 宽桌面首页左列能看到状态、主按钮、模式和开关，右列能看到手动组的当前节点；点某个组后打开节点页并看到该组
- 手机首页按状态、主按钮、模式、开关、手动组、连接与日志的顺序纵向排列；没有配置时看不到模式和开关
- 节点组可以选择默认、延迟或名称排序；自动组的节点行不能被选中；搜索无结果时显示没有匹配的节点
- 当前配置出现在配置列表第一条；添加层里能区分订阅链接和本地文件；覆写未保存就关闭时，生效配置不变；主题在配置页，「连接与日志」在首页，两者都不在主导航
- 诊断页能区分未连接和没有当前连接；日志选错误后仍能看到失败行，且只有日志正文是等宽字
- Android 从首页进入按应用排除，排除一项后返回首页，该项保持已排除

### R21 产品名称

行为：使用者可见的应用名称是 Billow。窗口标题、关于信息、桌面显示名和 Android 应用名都使用这个名字。

适用与失败边界：四个平台都适用。界面其余文字仍按 R7 使用简体中文。名称不使用轻澜、Zephyr、FlClash、Sparkle、Clash Verge 或观澜。仓库目录名尚未指定，不要求与显示名相同。

验收：

- 在 Windows、macOS、Linux 和 Android 上，应用窗口或系统应用列表中看到的名称是 Billow
- 首页和关于信息中的产品名也是 Billow，而不是上述其他客户端的名字

## 不做事项

### R8 快捷磁贴

行为：不提供 Android 快捷设置磁贴，也不能从磁贴开关代理。

适用与失败边界：Android 上的开启与关闭仍按 R4 在应用内完成。

验收：

- 系统快捷设置中没有本程序的代理开关磁贴

### R9 全局热键

行为：不提供全局热键来开关代理或切换节点。

适用与失败边界：桌面与 Android 的代理开关仍通过应用内操作完成。

验收：

- 应用内没有可设置并生效的全局热键

### R10 Android TV

行为：不把 Android TV 作为可操作目标，不提供电视界面。

适用与失败边界：手机和平板形态的 Android 仍按 R4 交付。电视设备上的安装或操作不作为通过条件。

验收：

- 交付范围的操作说明和界面不包含 Android TV 专用入口

### R11 WebDAV 备份

行为：不提供通过 WebDAV 备份或恢复配置。

适用与失败边界：配置的添加与生效仍按 R1 完成。不因缺少 WebDAV 而改变 R1 的验收。

验收：

- 界面中没有 WebDAV 地址，也没有通过 WebDAV 备份或恢复的操作

### R12 请求与 DNS 明细

行为：不提供请求明细视图，也不提供 DNS 查询明细视图。

适用与失败边界：当前连接和运行日志仍按 R6 交付。没有这两类明细不影响 R6 通过。

验收：

- 界面中没有逐条请求明细，也没有 DNS 查询明细

### R13 Sub-Store

行为：不集成 Sub-Store，也不提供多订阅组合后再生成内核配置的订阅整理。

适用与失败边界：多份配置仍按 R1 分别保存，同一时间只启用一份。

验收：

- 界面中没有 Sub-Store 的连接、同步或组合订阅操作

### R14 双内核切换

行为：不提供稳定版与预览版两套内核之间的切换。

适用与失败边界：使用者只使用客户端当前带有的那一套内核。内核能否启动仍按 R1 判断。

验收：

- 界面中没有稳定版与预览版内核的切换项

### R15 连接内容查看

行为：不提供连接载荷、请求正文或响应正文的查看。

适用与失败边界：当前连接的识别仍按 R6 交付。不能查看正文不影响 R6 通过。

验收：

- 从当前连接无法打开载荷或报文本体
