# 需求：补齐 mihomo 运行时能力与常用配置项

日期：2026-11-19

## 一屏摘要

- 目标：补齐 mihomo 控制器已提供、Billow 尚未承接的运行时操作，以及设置中还不能覆盖的常用配置项，延续 R22–R27 的 mihomo 对齐工作。
- 使用者：订阅中含自动选择组的普通用户；需要排查 DNS、调整路由或共享代理的进阶用户。
- 范围与优先级：P1 运行时能力 R28–R31（固定自动组节点、隐藏组、关闭全部连接、DNS 查询）；P2 配置项 R32–R34（TUN 路由地址、嗅探细项、出入站）；P3 内核维护 R35。
- 关键约束：不打扰普通用户。新内容只出现在已有菜单、弹窗或"高级"折叠中；新设置均提供"跟随配置"，生效配置概览（R22）按"Billow"来源标注。
- 失败边界：内核未运行时运行时操作禁用并说明原因；内核接口报错时显示内核原因且界面状态不变。
- 依据：R28–R31、R35 依赖的控制器接口已对照内置 mihomo v1.19.34 源码核实（见来源）；R35 不使用 mihomo `/restart`，由 Billow 自行停止并重新启动内核。
- 成功标准：每项在 demo 后端下可按验收复现，并有前端与 Rust 回归测试。
- 不做：外部控制器与外部面板（R36）；listeners / tunnels / sub-rules 图形化编辑（R37）。

## 完整需求

### R28 自动组固定与解除固定（P1）

行为：

- `url-test` 与 `fallback` 组在首页、代理页和命令面板中可以像 `select` 组一样点选节点；点选后该组固定使用此节点，组卡片显示"已固定"标记。
- 已固定的组提供"恢复自动"操作，执行后组重新按测速或可用性选择节点，"已固定"标记消失。
- 固定状态与 `select` 组的已选节点一样，在重新连接、切换回同一配置或重载配置后恢复。
- 其他自动类型的组（如 `load-balance`、`smart`）保持不可手动选择。

适用与失败边界：

- 内核未运行时不能固定或恢复自动，并提示"内核没有运行"。
- 内核拒绝固定时提示失败原因，组显示的当前节点保持不变。

验收：

- demo 中对一个 url-test 组点选非当前最快的节点后，组当前节点变为该节点并显示"已固定"；断开再连接后仍为该节点且带"已固定"。
- 对已固定的组点击"恢复自动"后，"已固定"消失，当前节点由组策略决定。
- load-balance 组的节点仍不可点选。

### R29 遵守代理组 `hidden: true`（P1）

行为：配置中写了 `hidden: true` 的代理组，不出现在首页组选择、代理页分组列表和命令面板中；它仍可作为其他组的成员显示在链式代理的中转路径里，生效配置概览的代理组数量照常计入。

适用与失败边界：所有组都被隐藏时，代理页显示空状态说明"配置中的代理组均已隐藏"，而不是"还没有可显示的节点"。

验收：

- demo 配置含一个 `hidden: true` 的组时，代理页、首页组选择和命令面板中都搜不到该组；概览中代理组数量包含它。

### R30 关闭全部连接（P1）

行为：连接页提供"全部关闭"。没有筛选条件时关闭所有活动连接；存在搜索或筛选时，按钮文案改为"关闭筛选结果"，只关闭当前列表中的连接。执行前弹出确认，并写明将关闭的连接数。

适用与失败边界：

- 没有活动连接或筛选结果为空时按钮禁用。
- 查看"已关闭连接"列表时不显示此按钮。
- 部分连接关闭失败时，提示失败数量，已关闭的连接从列表移除。

验收：

- demo 中有 12 条连接、筛选后剩 3 条时，确认框显示"关闭 3 条连接"，执行后其余 9 条仍在列表中。
- 无筛选时执行"全部关闭"，活动连接列表变为空。

### R31 DNS 查询工具（P1）

行为：在内核设置的 DNS 分页中提供"DNS 查询"入口，命令面板也提供"DNS 查询"。输入域名，选择记录类型（A、AAAA、CNAME、MX、TXT、NS、SRV、HTTPS，默认 A），使用内核当前生效的 DNS 配置解析，显示每条结果的类型、值、TTL 和本次耗时。

适用与失败边界：

- 内核未运行时入口可打开，但查询按钮禁用并说明原因。
- 域名为空或格式无效时不发起查询并提示。
- 无记录、超时或内核返回错误时，显示对应原因（如"没有找到记录"及内核返回的状态码）。

验收：

- demo 中查询 `example.com` 的 A 记录，显示至少一条 IP 结果、TTL 与耗时。
- 输入 `not a domain` 时提示格式无效，且不产生查询请求。

### R32 TUN 路由地址（P2）

行为：TUN 设置的"高级"折叠中新增：

- "不走 TUN 的地址"，写入 `tun.route-exclude-address`；
- "只让这些地址走 TUN"，写入 `tun.route-address`。

两项均为 IP 或网段列表，默认"跟随配置"；有覆盖时说明文字给出配置中的原值并带"已覆盖"标记。

适用与失败边界：

- Android 不显示（使用 VPN 与分应用规则）。
- 无法识别的条目不保存，并指出具体条目。
- TUN 设置的"恢复默认"与"全部跟随配置"都会清除这两项。

验收：

- 在"不走 TUN 的地址"填 `192.168.0.0/16` 并保存，运行配置的 `tun.route-exclude-address` 含该网段，概览对应行带"Billow"标签。
- 填 `300.1.1.0/24` 时提示该条目无效，运行配置不变。
- `?demo=android` 下看不到这两项。

### R33 嗅探细项（P2）

行为：打开嗅探后，嗅探设置下方出现"高级"折叠，可设置：

- 各协议（HTTP、TLS、QUIC）的嗅探端口；
- 强制嗅探域名 `force-domain`；
- 跳过嗅探域名 `skip-domain`；
- 是否用嗅探结果覆盖目标地址 `override-destination`。

每项默认"跟随配置"，有覆盖时带"已覆盖"标记。

适用与失败边界：

- 嗅探关闭时整块隐藏。
- 端口条目只接受端口或 `起-止` 范围，无效条目不保存并指出。
- 关闭总开关不清除已保存的细项，再次打开后恢复。

验收：

- 打开嗅探，将 TLS 端口设为 `443,8443` 并保存，运行配置 `sniffer.sniff.TLS.ports` 为这两个端口。
- 在 TLS 端口中填 `70000` 时提示无效，运行配置不变。

### R34 出站网卡、路由标记与更多入站端口（P2）

行为：内核设置"高级内核与测速选项"中新增：

- 出口网卡（`interface-name`），Android 不显示；
- 路由标记（`routing-mark`），只在 Linux 显示；
- SOCKS 端口（`socks-port`）、HTTP 端口（`port`），Android 不显示（Android 继续强制关闭这些入站，避免影响 VPN 路由）；
- 透明代理端口：`redir-port` 只在 Linux 与 macOS 显示，`tproxy-port` 只在 Linux 显示（mihomo 只在 Linux 实现 tproxy）。

各项默认"跟随配置"，可设为具体值或"关闭"（端口写 0 / 不写网卡）。局域网共享地址提示（R23）在 SOCKS 或 HTTP 端口启用时一并列出。

适用与失败边界：

- 端口须在 1–65535，且不能与混合端口或其他已设端口重复；冲突时不保存并指出冲突项。
- 出口网卡名称含空白时不保存。
- 端口被占用导致内核启动失败时，沿用混合端口占用的错误提示与就地修正方式，并指出是哪一种入站端口。
- 已保存的端口后来与生效的混合端口相同（例如切换到混合端口不同的配置）时，不阻止其他设置保存，但在该端口行显示冲突警告。

验收：

- 设置 SOCKS 端口 `7891` 并保存，运行配置含 `socks-port: 7891`，概览入站分组显示该端口并带"Billow"标签。
- 将 HTTP 端口设为与混合端口相同的 `7890` 时提示端口冲突，运行配置不变。
- Windows 与 Android 下看不到路由标记和透明代理端口；macOS 只显示 redir 端口；Android 看不到 SOCKS/HTTP 端口与出口网卡。
- 已保存 SOCKS 端口 `7891` 后，生效混合端口变为 `7891` 时，SOCKS 端口行显示"与当前混合端口 7891 相同"的警告。

### R35 内核维护操作（P3）

行为：

- 内核设置提供"重启内核"。确认后 Billow 停止并以当前生效配置重新启动内核（不使用 mihomo `/restart`），期间首页显示重启中；完成后恢复原有的接管方式（系统代理、TUN 或 VPN）和出站模式。Windows 上已为 TUN 授权时，重启复用已提权的进程，不再弹出 UAC。
- 日志级别为 `debug` 时，额外显示"回收内存"，执行后提示完成，并在首页内存读数刷新后体现变化。

适用与失败边界：

- 未连接时"重启内核"禁用。
- 重启失败时显示内核错误，并沿用现有的启动失败提示与重试。
- 日志级别不是 `debug` 时不显示"回收内存"。

验收：

- 已连接且开启 TUN 时执行重启，完成后 TUN 仍开启、出站模式与之前一致。
- 日志级别为 `info` 时看不到"回收内存"；改为 `debug` 后出现。

## 不做事项

### R36 不开放外部控制器与外部面板

不提供修改 `external-controller`、`secret`、`external-ui` 的设置，也不内嵌或打开第三方面板，延续 2026-11-08 需求的约束。可核查：设置与概览中没有可编辑的控制器地址或密钥，`secret` 不离开后端。

### R37 不做高级结构的图形化编辑

`listeners`、`tunnels`、`sub-rules`、`proxy-providers` 与 `proxy-groups` 结构不提供表单编辑，仍通过覆写修改；概览照常显示其数量或原文。

## 来源

- 用户要求"增强跟补齐对 mihomo 的支持"，并选择运行时能力与配置项两者都做（R28–R35）。
- `docs/requirements/2026-11-08-mihomo-config.md`：已有能力 R22–R27、"不打扰"约束、来源标注与不暴露控制器的边界（摘要、R32–R34、R36）。
- `src-tauri/src/nodes.rs#is_manual`：只有 `select` / `selector` 视为可手动选择，`parse_proxy_groups` 未读取 `hidden`（R28、R29）。
- `src/lib/backend.ts`：只有单条 `closeConnection`，没有关闭全部、DNS 查询、重启或回收内存命令（R30、R31、R35）。
- `src-tauri/src/profile.rs#KernelSettings`、`TunSettings`：嗅探只有总开关，TUN 无路由地址项，入站只有混合端口，无出口网卡与路由标记（R32–R34）。
- `src/lib/format.ts`：已识别 `smart` 组类型，但它属于自动组（R28 边界）。
- mihomo v1.19.34 `hub/route/proxies.go`、`adapter/outboundgroup/{urltest,fallback,util}.go`：url-test/fallback 支持 `PUT`/`DELETE /proxies/{组}` 固定与解除，`/proxies` 输出 `fixed` 与 `hidden`；Fallback 固定失效节点时先记录、再最长测速 5 秒后才应答（R28、R29）。
- mihomo `hub/route/connections.go`、`dns.go`、`restart.go`、`server.go`：`DELETE /connections[/{id}]`、`GET /dns/query`、仅 debug 级别挂载的 `PUT /debug/gc`；`/restart` 会重新执行原启动参数，与 Billow 热重载后删除运行文件冲突，故 R35 不使用（R30、R31、R35）。

## 非阻塞未知

- Windows 已提权进程内重启内核（R35）、Android 重启后重新建立 VPN 尚未在真机上验证；发布前需在对应平台实测。
