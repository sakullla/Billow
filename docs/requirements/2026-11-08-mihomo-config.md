# 需求：更多 mihomo 配置项与生效配置查看

日期：2026-11-08

## 一屏摘要

- 目标：让用户看懂内核实际在用的配置，补上局域网共享、TCP 保活、GEO 低内存加载等常用设置，并与 mihomo v1.19.34 对齐（R22–R26）
- 使用者：需要核对配置、共享代理给其他设备，或在手机上调优耗电的 Billow 用户
- 关键约束：不打扰普通用户。新内容只出现在已有的弹窗、"高级"折叠里，或在相关开关打开后才出现；默认界面不新增常驻元素
- 成功标准：每项在 demo 后端下可按验收复现，并有前端与 Rust 回归测试
- 不做事项：不暴露外部控制器（external-controller）与密钥；不做任意 YAML 键的图形化编辑（仍用覆写）

## 完整需求

### R22 生效配置概览

行为：

- "生效配置"弹窗分"概览"和"YAML"两个标签；两者高度一致，切换时弹窗不跳动。
- 概览按入站、出站、DNS、TUN、嗅探与 GEO、运行分组，以中文标签列出常用选项。
- 节点、代理组（按类型细分）、代理集、规则、规则集只显示数量。
- 每项标出来源：
  - 配置文件原值不标；
  - 被覆写修改的标"覆写"；
  - 被 Billow 设置覆盖的标"Billow"；
  - 悬停标签可看到原值；
  - 配置未设置的核心项显示"默认 · 值"。
- 冷门项（如路由标记、出口网卡、保活间隔）只在配置写了时出现。
- 其余未单独说明的顶层字段收进折叠的"其他字段"。
- 可按文字或 YAML 键名搜索，可按来源筛选（仅在存在覆写或 Billow 覆盖时出现）。
- 能在 Billow 里修改的项，整行可点，跳到对应设置分页或页面。

入口：

- 配置卡片菜单。
- 覆写编辑器底部链接，直接打开 YAML 标签。
- 内核设置的"生效配置"行。
- 命令面板"查看生效配置"。
- 上次选择的标签会被记住。

适用与失败边界：

- 密码、密钥、私钥、令牌与 `secret` 不离开后端；`authentication` 只显示用户名。
- 没有启用配置时，入口禁用并说明原因。
- 读取失败时在对应标签内显示错误。
- Android 不显示 TUN 分组。

验收：

- 打开局域网连接后查看概览，"局域网连接"显示"开启"并带"Billow"标签，悬停显示"配置中为 关闭"。
- 搜索 `enhanced-mode` 只剩"域名映射"一行，点击后进入 DNS 设置。
- 后端返回的概览 JSON 中不包含配置里的任何密码与 secret 原文。

### R23 局域网共享

行为：内核设置中打开"局域网连接"后，下方展开一块局域网设置：

- 显示其他设备应填写的地址（本机局域网 IP:端口），点击即复制。
- 访问认证：可选的用户名与密码，密码可显隐。
- 允许的设备：IP 或网段列表，逗号分隔。

修改后出现"撤销 / 保存"。写入 mihomo 的 `authentication`、`lan-allowed-ips`，并始终加入回环地址（`127.0.0.1/8`、`::1/128`）的免认证与放行，保证本机系统代理和本地应用不受影响。

适用与失败边界：

- 只在能确定本机私有 IPv4 地址时显示具体地址（开着 TUN 或其他 VPN 时可能取不到），否则显示通用说明。
- 只填用户名或只填密码、用户名含空格或冒号、无法识别的 IP 条目，都不保存并提示原因。
- 局域网连接关闭时整块隐藏。
- "全部跟随配置"会一并清除。

验收：

- 打开局域网连接后看到 `192.168.1.23:7890`（demo）。
- 只填用户名点保存会提示"用户名和密码需要同时填写"。
- 填写 `alice / s3cret` 与 `192.168.1.0/24，10.0.0.8` 后保存，生效配置中的认证显示 `alice`，允许来源包含回环地址。

### R24 TCP 保活

行为：内核设置"高级内核与测速选项"中新增"TCP 保活"：跟随配置 / 15、30、60、120 秒 / 关闭。选间隔时写 `keep-alive-interval`，选关闭时写 `disable-keep-alive: true`。说明文字给出配置文件中的原值，覆盖后带"已覆盖"标记。

适用与失败边界：mihomo 在 Android 上强制关闭 TCP 保活，Android 不显示此项；间隔限制在 5–3600 秒。

验收：

- 选择"关闭"后运行配置含 `disable-keep-alive: true` 且没有 `keep-alive-interval`。
- `?demo=android` 下"高级"折叠里没有 TCP 保活。

### R25 GEO 加载方式（低内存模式）

行为：资源页"GEO 数据库"弹窗新增"加载方式"：默认 / 低内存 / 标准，写入 `geodata-loader`（`memconservative` / `standard`）。默认沿用配置；配置也未设置时内核即使用低内存模式，说明文字写明这一点。生效配置概览显示"GEO 加载方式"，未设置时为"默认 · 低内存"。

验收：

- 打开 GEO 设置，加载方式默认选中"默认"；选"标准"后保存为 `standard`，概览中该行显示"标准"并带"Billow"标签。

### R26 与 mihomo v1.19.34 对齐

行为：

- **全局 TLS 指纹**：`global-client-fingerprint` 已被 mihomo 移除（Billow 内置的 v1.19.34 遇到它只打错误日志并忽略），Billow 不提供该设置。配置文件仍带此项时，概览显示"<值>（内核已移除，不生效）"，帮助理解日志中的报错。
- **TUN 协议栈**：新增"默认"，不写 `stack`，依次跟随配置、内核默认（v1.19.32 起为 Mips 自研栈，更早为 gVisor），避免把旧内核不认识的栈写进去。新安装与"恢复默认"使用它；已保存的选择不迁移（当前只有作者自用，手动切换即可）。后端也接受 `mips`。
- **Fake-IP 过滤模式**：新增"规则"（`rule`），说明文字给出规则写法示例。
- **概览补充字段**：`lan-disallowed-ips`、`tun.dns-mode`、`dns.fake-ip-filter-mode`、`geox-url`、`global-ua`、`etag-support`；协议栈与 GeoIP 格式未设置时显示内核默认值。

验收：

- TUN 设置的协议栈默认选中"默认"，说明含 Mips；运行配置中不含 `tun.stack`。
- DNS 覆写下选择"规则"并保存后，`fake-ip-filter-mode` 为 `rule`。

## 来源

- 用户要求"支持更多的 mihomo 配置跟查看，但是要不影响用户观感跟使用"。
- 走查：原"查看生效配置"只有整段 YAML，看不出哪些值是 Billow 覆盖的；局域网连接打开后没有地址提示，也没有任何访问控制。
- `src-tauri/src/profile.rs#apply_settings`：设置的叠加顺序为配置文件 → 覆写 → Billow 设置，概览按这三层判定来源。
- mihomo 官方文档（MetaCubeX/Meta-Docs `docs/config/general.md`、`inbound/tun.md`、`dns/index.md`，2026-07 更新）：全局指纹弃用、Android 强制关闭保活、`geodata-loader` 默认 `memconservative`、TUN 默认 `mips`、`fake-ip-filter-mode: rule`。
- mihomo v1.19.34 源码（Billow 内置内核）：`config/config.go` 中 `DefaultRawConfig` 的默认值，以及配置含 `global-client-fingerprint` 时输出的移除提示；`constant/tun.go` 自 v1.19.31 起支持 `mips`，v1.19.32 起为默认。
