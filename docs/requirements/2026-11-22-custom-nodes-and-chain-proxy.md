# 需求：自建节点、链式代理与免写配置模式

日期：2026-11-22

## 一屏摘要

面向使用机场订阅但需要搭配自建干净 IP 落地（链式代理），以及仅持有自建优化线路节点但不愿手写 Mihomo YAML 配置的 Billow 桌面端与 Android 用户，提供独立于订阅的自建节点资产库（R1）、含 `anytls://` 在内的多形态节点录入与编辑（R2）、可视化链式代理配置（R3）、机场订阅无感叠加落地且支持随时关闭（R4）、纯自建节点零配置开箱分流（R5）、轻量「指定流量走落地」规则（R6）、编译前校验与回滚保护（R7）、低心智负担与复用现有菜单的渐进式体验约束（R9），以及发布工作流更新说明与 `AGENTS.md` 发版规范（R10）。所有自建节点与链式/分流配置均跨订阅持久保存并纳入现有本地与 WebDAV 备份（R1）。关键假设：预设分流列表复用 Billow 现有规则集/Geo 机制，单节点 YAML 片段放行当前内核支持的任意协议字段（R2、R5、R6）。不做全协议可视化表单、全量通用规则编辑器、服务器运维及流媒体解锁检测（R8）。

## 完整需求

### R1 独立「自建节点」资产库与跨订阅持久化

行为：

- Billow 复用现有页面与菜单结构（不新增单独的一级导航入口，将自建节点管理自然融入现有「配置」与「代理」上下文），独立于具体机场订阅持久化管理个人节点，支持查看节点列表、新增、编辑、重命名、启用/停用、备注、删除与延迟测试。
- 当用户更新、切换或删除任意机场订阅时，自建节点资产及其链式代理与指定落地规则保持不变，不会被订阅内容覆盖或清空。
- 自建节点资产、链式关系与指定落地规则纳入现有本地 JSON 备份导出/恢复与 WebDAV 备份/恢复范围，导出与恢复提示继续沿用敏感信息确认机制。

适用与失败边界：

- 适用于桌面端与 Android 端。
- 停用某个自建节点时，该节点不参与本次运行配置编译，也不出现在运行态节点选择中，但保留其配置便于再次启用。
- 若删除或停用的自建节点正被其他链式节点或「指定流量走落地」规则引用，需在操作前或保存时明确提示受影响项，避免静默失效。

验收：

- 前置：已导入一个机场订阅并新增 1 个自建落地节点。执行订阅更新或切换至另一个订阅后，该自建节点及配置仍在列表中且可正常生效。
- 前置：存在自建节点与链式配置。执行本地导出或 WebDAV 上传备份，清空后从备份恢复，自建节点、链式关系与指定落地规则完整还原。
- 前置：将某自建节点切换为停用并应用生效后，该节点不再注入当前运行配置；重新启用后自动恢复注入。

### R2 多形态节点录入与编辑（含 `anytls://`）

行为：

- 支持以下三种节点录入与编辑方式：
  1. **分享链接批量导入**：一次粘贴单条或多条分享链接，或 Base64 编码的节点列表，原生解析 `vless://`、`vmess://`、`trojan://`、`ss://`、`hysteria2://`（含 `hy2://`）、`tuic://`、`anytls://`、`socks5://`（含 `socks://`）、`http://` / `https://`。
  2. **SOCKS5 / HTTP 快捷表单**：提供简洁表单手动填写或修改名称、协议（SOCKS5/HTTP）、服务器、端口、用户名、密码与 TLS 开关，适配常见住宅/家宽落地无标准分享链接的场景。
  3. **单节点 YAML 片段导入与高级编辑**：支持直接粘贴或编辑单个 Mihomo `proxies` 条目 YAML（含 WireGuard、AnyTLS 高级参数、自定义传输层等），作为全协议兜底能力。
- 导入前向用户展示解析预览（成功条数、协议类型、节点名称与跳过/失败条目及原因）；若导入名称与已有节点重名，自动生成不冲突的名称并提示。

适用与失败边界：

- 假设：单节点 YAML 片段允许任何当前运行 Mihomo 内核支持的协议字段，应用层仅做 YAML 结构与必填键（如 `name`、`type`、`server`、`port`）校验。
- 批量粘贴包含部分损坏链接或不支持协议时，不得因单条失败阻断其余有效节点导入；需逐条报告失败原因。
- 全部内容均无效或缺少必填字段时，阻断导入并给出明确中文错误说明，不产生半成品节点。

验收：

- 前置：打开自建节点导入入口。输入包含 `vless://`、`anytls://`、`hysteria2://` 与 1 条损坏链接的多行文本后，预览清晰列出 3 条可导入节点与 1 条失败原因；确认导入后 3 条有效节点入库且协议标识正确。
- 前置：通过 SOCKS5/HTTP 快捷表单填写服务器、端口与账密并保存后，生成可用节点并可再次打开表单修改。
- 前置：粘贴 1 段合法的 WireGuard 或 AnyTLS Mihomo 单节点 YAML 片段并保存后，节点正常入库；粘贴非法 YAML 语法时被阻断并提示具体错误位置/原因。

### R3 可视化链式代理（`dialer-proxy`）

行为：

- 用户可为任意自建节点配置前置代理（对应 Mihomo `dialer-proxy`），无需手写 YAML：
  - **随前置策略组切换（默认推荐）**：将落地节点的前置指向当前配置中的指定策略组（例如机场主代理组或专用的「链式前置」策略组），用户在代理页切换前置节点即可动态更换整条链路的中转入口。
  - **固定单个节点**：将前置锁定为当前配置中的某个具体节点，或另一个已启用的自建节点（支持「自建中转 → 自建家宽落地」多跳组合）。
  - **直连出口（无前置）**：直接经本地网络访问该自建节点（适用于优化线路落地）。
- 代理页与节点选择器中，链式节点清晰展示链路标签与完整路径（前置 → 落地），测速反映经前置到达落地的真实端到端延迟。

适用与失败边界：

- 检测并阻断自引用（节点前置指向自身）与多跳循环引用（如 A → B → A），保存或编译前明确提示环路节点名称。
- 当链式节点绑定的「固定前置节点」在机场订阅更新后消失，或引用的前置自建节点被停用/删除时，在配置编译前与界面状态中明确标记前置不可用并引导重新选择，不静默退化为直连（避免用户误以为走链式而暴露本地直连行为）。

验收：

- 前置：存在机场订阅与 1 个自建落地节点。将该落地的前置设为机场前置策略组并连接后，运行配置中该落地携带对应 `dialer-proxy`，在代理页切换前置策略组的选中节点可实时改变链式出口路径。
- 前置：存在自建中转节点 A 与自建落地节点 B。将 B 的前置设为 A 后可正常保存并生效；若再尝试将 A 的前置设为 B，系统拦截并提示循环引用错误。
- 前置：链式落地绑定了机场中的固定节点 X，随后订阅更新移除了节点 X。重新应用或查看节点列表时，界面明确提示前置节点缺失并阻止静默回退直连。

### R4 机场订阅无感叠加自建落地（支持随时关闭）

行为：

- 当用户启用任意机场订阅或本地完整 YAML 配置，且「叠加自建节点与落地」开关开启时，所有已启用的自建节点（含链式落地）自动注入运行配置与代理页可选分组，用户无需编写任何覆写脚本。
- 提供显式的**一键关闭/开启**控制（支持全局关闭订阅叠加，以及按需关闭指定落地规则）：关闭后，无需逐条停用自建节点或规则，机场订阅完全按原始配置（及用户自有手写覆写）运行，不注入任何自建节点、落地分组或指定落地规则；重新开启后原样恢复全部配置。
- 提供清晰的落地入口：用户既可以直接在代理页将主代理或落地分组切换到某个自建落地，实现全部代理流量走干净 IP，也可以保留原有机场节点分组正常使用。
- 与现有单配置手写 YAML/JS 覆写共存，且注入过程不修改原始订阅内容；当自建节点与订阅内节点重名时，以确定策略规避命名冲突且不破坏订阅原有策略组引用。

适用与失败边界：

- 当叠加开关关闭，或当前没有任何已启用的自建节点时，运行配置与现有行为保持完全一致，不额外增加空分组或冗余配置。
- 关闭订阅叠加不影响用户保留自建节点资产（R1），也不阻止用户显式切换到纯自建开箱模式（R5）。
- 若某个自建节点因前置缺失等原因无法参与当前订阅编译，给出清晰告警并明确告知受影响的落地节点，不导致整份机场配置无法使用（除非用户显式选择了该失效节点作为必填依赖）。

验收：

- 前置：已启用一份正常机场订阅，且存在 1 个已启用的链式自建落地节点。开启叠加并连接后，在代理页可直接看到并选中该自建落地节点，且原有机场策略组与节点保持可用。
- 前置：在上述状态下，关闭「叠加自建节点与落地」开关并应用生效后，代理页不再显示自建节点与落地分组，指定落地规则同步暂停，机场配置恢复纯净运行；此时自建节点列表与规则数据仍完整保留，重新开启后立即恢复生效。
- 前置：停用全部自建节点后重新应用配置，代理页不再显示自建落地分组，运行配置恢复与未配置自建节点时一致。

### R5 纯自建节点「免写配置」开箱模式

行为：

- 当用户没有任何机场订阅（或主动选择使用纯自建配置）且至少存在 1 个已启用的自建节点时，可直接以「自建配置」模式一键连接，全程无需手写或导入 Mihomo YAML 文件。
- Billow 自动为已启用的自建节点生成完整可运行的 Mihomo 配置，包含：
  - 基础代理组（手动选择、自动测速/故障转移等常用入口，并兼容链式落地节点）。
  - 自动分流规则：默认区分国内直连与海外代理（复用 Billow 已有 Geo/规则资源与局域网直连），确保开箱即可日常上网。
  - 可靠的默认 DNS 配置，并完整联动现有设置页中的端口、系统代理、TUN、DNS 覆写及应用分流设置。
- 新增、编辑、启停或删除自建节点后，自动同步更新该配置并在已连接时平滑触发重载或提示生效。

适用与失败边界：

- 假设：开箱分流默认采用「国内直连 + 海外代理 + 私有地址直连」策略，Geo 数据沿用 Billow 现有内置/下载资源管理。
- 若所有自建节点均被停用或删除，阻止启动连接并提示「请先添加或启用至少一个自建节点」。
- 若内置 Geo 资源缺失且无法读取，给出可理解的中文错误与修复入口，不静默退化为全流量直连或崩溃。

验收：

- 前置：全新环境无任何机场订阅，仅通过粘贴 1 条自建优化线路节点（如 `vless://` 或 `anytls://`）导入并启用。用户无需编写任何 YAML，直接点击连接即可成功启动内核并正常代理。
- 前置：在上述纯自建连接状态下，访问国内地址走直连、海外地址走自建节点，代理页可正常切换节点与测速，设置页修改端口/TUN/规则与全局模式均正常生效。
- 前置：停用全部自建节点后尝试连接纯自建模式，连接被拦截并展示明确的中文提示。

### R6 轻量「指定流量走落地」规则

行为：

- 用户无需编写 YAML，即可在界面中配置「指定流量走落地」规则，让日常流量继续走主代理（如机场），仅将指定流量定向路由到选定的自建落地或落地分组：
  - **常用场景预设**：支持一键勾选常见需要干净 IP 的服务预设（例如 AI 服务等），并为其指定目标落地。
  - **自定义域名规则**：支持添加、编辑、启停与删除自定义域名/域名后缀（如 `example.com`、`.example.com` 或 `full.example.com`）并指定目标落地。
- 生效优先级：用户的指定落地规则自动插入到分流规则的高优先级位置（位于私有地址/局域网直连之后、通用代理/兜底规则之前），同时兼容机场订阅叠加模式（R4）与纯自建开箱模式（R5）。
- 支持一键停用单条规则或全部规则，便于临时排查问题。

适用与失败边界：

- 假设：常用场景预设基于内建/现有 Mihomo 规则集机制维护，不要求用户手动维护域名清单。
- 对自定义域名输入进行格式校验（去除首尾空白、协议头误粘贴提示或规范化），拒绝空值或非法字符并给出清晰提示。
- 若某条规则指向的目标落地已被停用或删除，在规则列表高亮提示并跳过注入或阻断保存，避免生成指向不存在代理的损坏 Mihomo 配置。

验收：

- 前置：启用机场订阅并配置 1 个链式落地节点；在「指定流量走落地」中勾选 AI 服务预设并添加自定义域名 `ip.sb` 指向该链式落地。应用后查看生效配置与规则页，对应预设规则与 `ip.sb` 规则均位于通用分流之前且目标为该链式落地。
- 前置：将上述规则切换为停用并应用后，对应流量恢复按原主代理规则路由。
- 前置：规则指向的落地节点被停用后，规则界面明确提示目标节点不可用，且不会生成导致内核启动失败的配置。

### R7 编译前校验、错误定位与事务回滚保护

行为：

- 在任何自建节点、链式关系或指定落地规则变更并应用到内核前，先完成完整配置编译与合法性校验（包括协议字段、链式环路、前置可达性、规则目标存在性及命名唯一性）。
- 若编译或内核重载失败，自动保持上一次可用的运行配置与连接状态不中断，并在界面给出明确的中文失败原因与可定位到具体节点/规则的提示。

适用与失败边界：

- 覆盖桌面端与 Android 端所有生效路径（首次连接、运行时热更新、切换配置、订阅刷新后重新编译）。
- 不允许将半写入或损坏的节点/规则状态持久化到磁盘。

验收：

- 前置：当前已处于正常连接状态。用户修改某自建节点 YAML 引入非法字段或构造失效引用并尝试应用时，应用被阻断或自动回滚，现有连接不中断，界面展示明确中文错误与具体节点名称。

### R9 低心智负担与渐进式体验约束

行为：

- **复用现有菜单，不新增一级入口**：桌面端侧栏与移动端底栏保持现有导航项不变，不新增独立的一级「自建节点」或「链式代理」菜单入口；自建节点录入、编辑与开关收敛在现有「配置」页及导入/操作菜单中，链式落地的选择与路径查看收敛在现有「代理」页上下文中。
- **对纯机场用户零打扰**：当用户尚未添加任何自建节点，或已关闭订阅叠加开关（R4）时，首页、代理页与日常切换流程保持与现有产品一致，不出现空的「自建/落地」分组或多余空状态横幅。
- **渐进披露与直白语言**：录入时自动识别分享链接、Base64 与 YAML，默认只呈现必要信息，高级项（如固定单节点前置、单节点 YAML 编辑、指定域名规则）按需展开；界面文案使用面向目标的日常中文表达（如「前置代理」「通过机场中转」「仅指定网站走此落地」），不强迫用户理解 `dialer-proxy`、`proxy-groups` 等 Mihomo 内核术语；新增落地或启用纯自建模式时自动填充合理默认项，用户完成核心目标（粘贴节点 → 开启/连接）不超过最少必要步骤。

适用与失败边界：

- 适用于桌面端与 Android 端所有新增界面、文案与交互流程。
- 不得以“提供更多灵活性”为由新增一级导航入口，或在主路径叠加多步向导、复杂矩阵开关与非必要技术决策。

验收：

- 前置：在桌面端与 Android 端查看主导航（侧栏 / 底栏）。主导航项数量与层级与改动前一致，未新增单独的一级管理入口。
- 前置：全新或仅使用机场订阅的用户打开首页、代理页与配置页。界面不展示任何空的自建/落地分组或冗余概念提示，原有主路径步骤数不增加。
- 前置：仅有一条自建优化线路链接的新用户通过现有「配置」页入口导入节点并启动纯自建连接。全流程仅需粘贴导入与点击连接即可使用，无需理解或手动配置策略组、规则或 DNS。
- 前置：已有机场订阅的用户粘贴 1 条海外落地链接并开启「通过当前订阅中转」后，无需手写任何配置或理解 `dialer-proxy`，即可在代理页直接使用该落地节点。

### R10 发布工作流更新说明与 `AGENTS.md` 发版规范

行为：

- **面向用户的版本说明优先**：`.github/workflows/release.yml` 在创建或更新 Release 时，优先读取当前版本对应的手写/AI 撰写更新说明文件（`docs/releases/v<version>.md`），并将其作为 GitHub Release 正文主体（附带安装包说明与对比链接），同时同步写入 `latest.json` 的 `notes` 字段供应用内更新提示展示。
- **Commit 历史自动兜底**：若当前版本说明文件缺失或为空，发布脚本自动拉取上一发布 tag 至当前 tag 之间的 git commits，按 `feat`（新功能）/ `fix`（问题修复）/ 其他改动分组生成简洁中文更新说明，避免出现仅有 `Full Changelog` 链接的空白发布。
- **固化到 `AGENTS.md`**：在仓库根目录 `AGENTS.md` 中明确发版规范——控制单次发版粒度避免一次堆砌过多变更，每次发版前由 AI 梳理自上次 tag 以来的用户可见变更并撰写精炼的 `docs/releases/v<version>.md`，同步版本号后再打 tag 发布。

适用与失败边界：

- 发布说明生成逻辑抽离为可单测脚本（置于 `.github/scripts/`），支持本地自动化测试验证「读取版本说明文件」「缺失文件回退 git log 分组」「首个 tag 无上游 tag」等边界场景。
- `prepare` job 使用完整历史检出（`fetch-depth: 0`）以确保兜底 commit 汇总可访问上一版本 tag。

验收：

- 前置：仓库存在 `docs/releases/v0.1.43.md`（非空）。运行发布说明生成脚本时，输出正文直接采用该文件内容并附带安装包说明与 compare 链接，且 `latest.json` 包含对应更新说明。
- 前置：仓库不存在对应版本说明文件，且自上一 tag 以来存在 `feat:` 与 `fix:` 直推 commit。运行发布说明生成脚本时，自动按「新功能」「问题修复」输出中文分组条目，不再为空白。
- 前置：检查 `AGENTS.md`。其中明确包含发版粒度原则、`docs/releases/v<version>.md` 编写要求与发版前检查步骤。

## 不做事项

### R8 明确排除范围

- **不做全协议可视化参数表单**：除 SOCKS5 / HTTP 快捷表单外，其余协议的高级传输层/安全参数统一通过分享链接解析或单节点 YAML 片段编辑，不逐一维护数十种协议的庞大表单界面。
- **不做通用全量 Mihomo 规则编辑器**：不提供覆盖全部 Mihomo 规则类型、正则匹配与自由全表拖拽排序的编辑器；超出「常用预设 + 自定义域名走落地」的复杂分流仍由现有 YAML/JS 覆写能力承接。
- **不做自建节点部署/运维与流媒体解锁检测**：不涉及 VPS 搭建、面板管理或第三方流媒体解锁探测（延续 Billow 既有产品边界）。
