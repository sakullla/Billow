# 本地变更性能与内存复查

审查包含资源压缩、离线配置切换、资源页和新加的界面缩放。工作区期间已有改动提交为 v0.1.15（37c0f8c）；本轮保留这些行为，修正下面的具体开销和生命周期问题。

## 修正

- **压缩缓存命中**：原来会读入压缩包，再完整解压出一份约 57 MB 的内核副本来比较。现在使用带背压的流逐块校验解压长度与 SHA-256，同时计算压缩包哈希。ZIP 提取结果使用 Buffer 视图，避免再复制整个可执行文件。
- **重复磁盘写入**：压缩输出经流式哈希比对确认相同时保留文件和时间戳，损坏时才原子替换；GEO 原始缓存只有缺失或校验失败才重写。压缩使用异步接口，保持相同压缩参数和包内容。
- **GEO 首次初始化**：清单按需读取一次，并通过 BufReader 解析，避免每个资源重新打开、解析清单及 JSON 逐字节读文件。
- **界面缩放**：只保留一个进行中的缩放请求，合并其间的操作到最新值。安装、窗口测量和应用缩放都按生命周期核对结果；卸载取消定时器，迟到的安装不再添加监听器，重装也能纠正旧请求迟到造成的缩放。
- **资源页**：页面卸载后，不再因更新完成而请求新的完整资源列表；已发起的更新按原计划完成。迟到的 GEO 查询不会重新写回已离开的页面，也不会覆盖更新的查询结果。
- **离线配置切换**：内容和已应用覆写未变化时复用节点元数据缓存；下载新内容或改变覆写仍正确失效。

## 测量

同一份 56,698,738 字节内核、同一份已存在的压缩缓存，分别运行独立 Node 进程。两边都包含读取与解压上游归档，用 `/usr/bin/time -l` 和 `process.resourceUsage()` 观察进程峰值。

| 指标 | 原实现 | 修改后 |
| --- | ---: | ---: |
| 峰值 RSS | 277,968 KiB（约 271 MiB） | 218,288 KiB（约 213 MiB） |
| 缓存校验与输出耗时（单次） | 190.7 ms | 239.3 ms |

峰值减少约 21.5%，此次测量用约 49 ms 的额外构建时间换取较低内存。这是构建脚本的一次同机测量，不是应用运行时内存，也不是稳定性能保证。
