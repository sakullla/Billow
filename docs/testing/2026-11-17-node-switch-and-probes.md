# 节点切换与测速反馈

## 问题与对照

用户确认选中状态立即变化，但已有网页、下载和视频仍走旧节点。这是已建立连接继续复用原出站路径。Billow 原先只发送选择器 PUT，没有处理这些连接。

[Sparkle](https://github.com/xishang0128/sparkle/blob/master/src/renderer/src/pages/proxies.tsx) 在切换成功后按配置关闭全部或当前组连接；[FlClash](https://github.com/chen08209/FlClash/blob/main/lib/providers/actions/proxies.dart) 在切换成功后按设置关闭连接或重置连接池。

## 行为

- 默认开启「设置 → 通用 → 切换节点后重连」，可以关闭以保留长下载等现有连接。
- 只有选择器 PUT 成功且选择确实改变，才关闭经过该代理组的旧连接。失败、重复选择或离线保存选择都不触发关闭。
- 按 Mihomo chains 中与该组相邻的选中出站识别新旧路由，避免误伤其他组、新线路，以及嵌套链中恰好出现同名节点的情况。
- 完整读取连接 ID/链信息，不受连接页 500 行展示上限影响；关闭请求最多 4 个并发，具有总时限。部分关闭失败明确提示，保留已成功的新选择，不退回旧节点。
- 应用自行重新建立连接；不支持自动续传的下载或通话可能中断，因此提供关闭选项。
- 组测速即时显示「测速中」与完成计数，复用 node-test 事件逐节点显示结果。完成后的快照同步所有引用同名节点的组。
- 全部、分组、单节点测速共享运行状态，阻止重复提交；当前测速结束后清理等待状态。
- 测速从 16 个一批的屏障等待改为最多 16 个持续工作的线程，完成一个就开始下一个，慢节点不会拖住整批后续任务。
- 节点切换和测速前只读取所需的内核运行状态/节点目录，省去额外的完整连接统计查询。

## 验证

- HTTP 控制器测试：只删除匹配旧连接，保护其他组和新线路，正确编码 ID；覆盖超过 500 行的连接列表和空列表。
- 后端回归：切换失败不关闭、同节点不重复关闭、关闭开关生效、修改选项不重启内核、清理失败仍保留新选择。
- 线程池回归：第一个节点仍被阻塞时，第 17 个节点已经开始处理；结果最终保持输入顺序。
- 浏览器 Demo：点击后立即显示「已测 0/22」和 22 个等待标记；100 ms 后已完成 5 个、仍有 17 个等待；结束后等待状态为 0，无横向溢出。该测量只验证渲染反馈，不代表真实网络测速耗时。
- 真实 Mihomo v1.19.34 隔离回环测试：建立两组 TCP 长连接；切换一组后该组旧连接关闭，另一组继续收发，新连接使用新节点。未修改正在使用的系统代理/TUN。
- 前端完整测试 241 项通过，后端完整测试 160 项通过、7 项环境测试默认跳过；真实内核切换测试另外启用并通过。生产前端构建与 diff 检查通过。

测试中还移除了一个旧启动退出用例对无控制器 300 ms 宽限期的依赖，改用生产的控制器就绪判断，避免高负载下偶发误判。
